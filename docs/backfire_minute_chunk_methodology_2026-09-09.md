# Methodology: minute-chunking + boundary verification for the "Backfire" video

Covers how `youtube__pBo_2DYxfrY` ("Backfire: The Excommunication Story
of Tim Ballard," 3h52m13s) got split into per-minute clips, captioned,
and checked for cuts that sliced through a word — so this can be
reproduced on another long video, or the results trusted/audited later.

All work happened in `dl_wm/outputs/2026-09-07/youtube__pBo_2DYxfrY/`.
Source for every step below is the already-watermarked video
(`youtube__pBo_2DYxfrY_watermarked.mp4`, 1.56GB) — not the raw download.

## Step 1 — split into ~1-minute chunks

Single-pass **stream copy** (no re-encoding) via ffmpeg's segment muxer:

```
ffmpeg -y -i youtube__pBo_2DYxfrY_watermarked.mp4 -c copy -map 0 \
  -f segment -segment_time 60 -reset_timestamps 1 seg_%04d.mp4
```

Because it's a stream copy, each cut lands on the **nearest keyframe at
or after** the 60s target, not exactly on the second — actual segment
lengths in this video ranged roughly 54-67s, not a flat 60. This is why
step 3 (below) computes exact cumulative boundary timestamps from the
real output durations rather than assuming `minute * 60`.

Result: 233 segments (232 full-ish minutes + one ~3.4s tail), moved into
`minute_chunks/hour_<N>/minute_<NN>/youtube__pBo_2DYxfrY_h<N>_m<NN>.mp4`
— 60 minute-folders per hour, 53 in the partial 4th hour.

## Step 2 — caption every chunk

Ran the existing `bin/call_captions.py` (Whisper, "base" model, word
timestamps on) against every one of the 233 clips, writing a `.srt` +
`.whisper.json` sidecar next to each clip. Same approach was used
earlier for all 1053 `scene_split.py` clips from this same video.

**Machine note, not specific to this video:** this box has 3.2GB RAM and
a background-task watchdog that kills anything it decides is a memory
risk, sometimes even a single short Whisper call. Workaround that held
up across every batch this week: run the driving loop as a **fully
detached process** (`nohup ... & disown`, not the harness's own
backgrounding), and make the loop itself resumable (skip any clip that
already has an output file) so a kill costs at most the one file in
flight. Confirmed zero failures across all 233 clips run this way.

## Step 3 — find the real cut points

`_flat` segment durations were read back with `ffprobe` and summed
cumulatively, in file order, to get the **actual** elapsed-time position
of every one of the 232 internal joins between clips (not assumed
60/120/180... marks). Saved as `/tmp/minute_chunk_boundaries.json`
(list of `(hour, minute, own_duration, cumulative_end)`). Total matched
the source's own duration exactly (13933.225s) — confirms no gap or
overlap was introduced by the split.

## Step 4 — extract + caption a 6s window around every join

For each of the 232 real cut points, re-encoded (not stream-copy, so
this one IS frame-accurate) a 6-second window `[cut - 3s, cut + 3s]`
straight from the original watermarked source:

```
ffmpeg -y -ss <cut-3> -i youtube__pBo_2DYxfrY_watermarked.mp4 -t 6 \
  -c:v libx264 -preset veryfast -c:a aac edge_<N>_h<h1>m<m1>-h<h2>m<m2>.mp4
```

(`-ss` before `-i`, combined with re-encoding rather than stream copy,
gives an accurate seek in modern ffmpeg — fast, and correct.) Output to
`minute_chunks/_edge_checks/`. Then ran the same captioning step as
above on all 232 edge clips.

**Key property this all depends on:** because each edge clip is
`[cut-3, cut+3]`, the real minute_chunks cut point always falls at
exactly **t=3.0s** in that clip's own (clip-relative) timeline. That
turns "did we cut through a word" into a single fixed check per clip,
not something that has to be re-derived per boundary.

## Step 5 — detect mid-word cuts

`bin/check_edge_cuts.py` (new script, committed alongside this doc):
reads each edge clip's `.whisper.json`, collects word-level
`{word, start, end}` entries across all segments, and checks whether any
word's interval straddles t=3.0s (`start < 3.0 < end`). If so, the real
cut in `minute_chunks/` sliced that word in half.

Also flags "tight but clean" cuts — no word actually straddles 3.0s, but
the gap between the preceding and following word is under 0.15s, i.e.
close enough that Whisper's own timing imprecision could be masking a
real overlap.

**Result on this video: 153 of 232 boundaries (66%) cut through a word.**
64 were clean (a real pause at the cut), 14 clean-but-tight, 1 had no
speech at all. Full run log:
`minute_chunks/_edge_checks/edge_cut_report.txt`.

Not surprising — the original split (step 1) is a blind 60-second cut
with no silence-detection, so hitting mid-speech constantly is expected
on a talk-heavy video like this one.

## Step 6 — word-fix reference, not a re-cut

Decision: **don't re-split** the 153 affected boundaries. Instead,
`boundary_word_fixes.md` (`minute_chunks/_edge_checks/`, generated by a
small one-off script, not currently kept in `bin/`) lists, for every
mid-word cut, the whole intact word (plus one word of context each
side) as Whisper transcribed it from the **uncut edge clip** — since
the word survives whole there even though it's split across the two
real minute-chunk files. Use this to patch/verify a chunk's SRT at a
join without touching the actual video files.

## Files/scripts this produced

- `dl_wm/bin/check_edge_cuts.py` — mid-word-cut detector (committed,
  reusable on any similar edge-check set).
- `minute_chunks/_edge_checks/*.mp4` + `.srt` + `.whisper.json` — the
  232 boundary-verification clips and their transcripts.
- `minute_chunks/_edge_checks/edge_cut_report.txt` — full detector
  output.
- `minute_chunks/_edge_checks/boundary_word_fixes.md` — the 153-row
  word-correction reference.
- `/tmp/minute_chunk_boundaries.json` — the exact cumulative boundary
  timestamps (not yet moved into the repo; regenerate from `_flat`
  segment durations if this needs to be reproduced later, or move it
  into the project if it needs to persist).

## Verified no-speech clips (added 2026-09-10)

The subtitle-burn pass over all 1053 `scene_split.py` clips (SRTs sliced
from the master patched transcript per Step 6, burned in via
`call_burn_srt._burn_subtitles`) completed with 0 failures but skipped 12
clips that had no sliced SRT at all: `clip_02, clip_03, clip_115,
clip_415, clip_486, clip_719, clip_921, clip_922, clip_923, clip_924,
clip_925, clip_926`. All 12 are very short (1-6s each); six of them
(`921`-`926`) are consecutive micro-cuts spanning just 12801-12810s.

Concatenated all 12 (chronological order) and watched them directly:
**confirmed genuinely no speech** in any of them — correct behavior, not
a transcription gap or pipeline bug. Marked as verified by writing empty
(zero-cue) `.srt` files for these 12 clip_ids into `scene_clips/
subtitles/`, so a future rerun of the burn batch recognizes them as
intentionally-empty rather than re-flagging them as missing.

## Caveats

- All transcripts here are Whisper **base model**, not verified against
  a human re-listen except where explicitly flagged elsewhere (see
  `backfire_named_accusers_index.md` for passages already flagged as
  needing a direct listen).
- The word-fix reference trusts Whisper's transcription of the edge
  clip as more reliable than the two half-cut chunk transcripts for
  that one word — reasonable since the edge clip has the whole word
  with full context on both sides, but still a Whisper output, not a
  human transcription.
